## Scope and Source Hierarchy

Apply this reference to the original Sinclair ZX Spectrum 16K/48K and Spectrum+ hardware represented by `ZXSPECTRUM::Type::_STANDARD`. Do not transfer timings directly to 128K, +2, +2A, or +3 machines.

Keep these axes independent:

- RAM population: 16K or 48K.
- Video timing: PAL or NTSC.
- ULA type and PCB issue: 5C102E, 5C112E variants, 6C001E variants, and board modifications. Treat the later 7K010E and Amstrad gate arrays as out-of-scope comparison boundaries.
- Signal model: digital pixel output versus composite analogue artifacts.
- Timing origin: `/INT` assertion, frame counter zero, first display fetch, or CPU acknowledge.

Prefer evidence in this order:

1. `.codex/docs/ZXSpectrumULA.pdf`, Chris Smith, *The ZX Spectrum ULA: How to Design a Microcomputer*.
2. Sinclair Research, *ZX Spectrum Service Manual*, including Issues 2 and 3 circuit diagrams.
3. Zilog, *Z80 CPU User Manual*, for M-cycles, refresh, I/O sampling, HALT, WAIT/clock, and interrupts.
4. Measurements and calibrated tests: World of Spectrum 48K technical reference and RAMSOFT floating-bus guide.
5. Mature emulators and their tests as comparative implementations, not independent hardware proof.

## Machine Clocks and Raster

The board uses a 14 MHz crystal. The ULA derives a nominal 7 MHz pixel clock and a nominal 3.5 MHz Z80 clock. One CPU T-state spans two pixel clocks when the clock is not stretched.

For the classic PAL design:

- 448 pixel clocks = 224 CPU T-states per line.
- 312 lines per frame.
- 69,888 CPU T-states per frame.
- 256 active pixels and 192 active lines.
- The book describes 96 pixel clocks before the active picture and 96 after it, with visible and non-visible border components.
- A common logical layout is 8 vertical-sync lines, 56 top-border lines, 192 display lines, and 56 bottom-border lines.

For the book's NTSC design:

- 448 pixel clocks per line.
- 264 lines per frame.
- 59,136 CPU T-states per frame.
- 192 active display lines with different top/bottom margins.

These totals do not by themselves define the emulator's coordinate zero. Validate the position of `/INT`, sync, first fetch, and first visible pixel relative to that origin. ULA revisions can shift display timing by a T-state; record early/late timing instead of silently choosing one.

The frame interrupt is generated by the ULA. On the standard 48K PAL model it occurs once per 20 ms frame. Validate the level duration and the Z80 sampling boundary, not only a once-per-frame callback.

## Video Fetch and Display Encoding

The display file occupies `0x4000-0x57FF` (6144 bytes). The attribute file occupies `0x5800-0x5AFF` (768 bytes).

For active pixel coordinate `(x,y)`, with `x=0..255`, `y=0..191`:

```text
bitmap = 0x4000
       | ((y & 0xC0) << 5)
       | ((y & 0x07) << 8)
       | ((y & 0x38) << 2)
       | (x >> 3)

attribute = 0x5800 | ((y >> 3) << 5) | (x >> 3)
```

Each attribute byte:

- bits 0-2: INK;
- bits 3-5: PAPER;
- bit 6: BRIGHT;
- bit 7: FLASH.

Validate the two-stage pixel and attribute latches. The ULA fetches ahead of the pixels being displayed; a direct `(x,y)` read at draw time can produce correct static images while failing border-edge writes, floating bus, snow, and contention.

Within each active scanline, fetches form 16 groups of 8 T-states. The first four phases expose bitmap, attribute, next bitmap, next attribute; the next four are idle. The display consumes 32 bitmap bytes and 32 attribute uses per line.

FLASH swaps foreground and background for flashing cells. Treat its phase as frame-derived state and verify the selected transition period and reset behavior. BRIGHT changes RGB intensity but never the border, whose port value is only three bits.

Use patterns that expose latch phase:

- alternating `0xAA/0x55` bitmap bytes;
- adjacent cells with maximally different attributes;
- first and last active character;
- writes one T-state before and after a fetch;
- FLASH cells beside steady cells;
- all eight colours with and without BRIGHT.

## Memory Arbitration and Contention

The lower 16K RAM at `0x4000-0x7FFF` is shared with the ULA. The ULA drives independent multiplexed DRAM row/column addresses and has priority for display fetches. The CPU clock is inhibited/stretched to defer a conflicting CPU access.

Contention is a property of individual bus phases:

- opcode fetches from contended RAM;
- immediate bytes fetched from contended RAM;
- operand reads and writes;
- stack reads/writes;
- both accesses of read-modify-write instructions;
- block instruction iterations;
- refresh interactions where relevant;
- each affected phase of an I/O cycle.

The classic delay sequence is `6,5,4,3,2,1,0,0`, repeated across the active fetch window. In the World of Spectrum convention, the first contended 48K PAL T-state is 14335 after the frame `/INT` origin. Other sources can differ by one or more because they name another signal edge. Compare waveforms or derive the offset before declaring a bug.

After a delay, all later M-cycles occur later. Apply contention incrementally during execution; do not compare a post-execution access list with an unshifted raster and then add one aggregate pause.

I/O contention depends on both:

- A0 low: the ULA participates in the I/O cycle.
- high port byte in `0x40-0x7F`: the ULA can interpret the address bus as a contended-memory address.

The reference patterns are:

| High byte `0x40-0x7F` | A0 | Pattern |
| --- | ---: | --- |
| no | 0 | `N:1, C:3` |
| no | 1 | `N:4` |
| yes | 0 | `C:1, C:3` |
| yes | 1 | `C:1, C:1, C:1, C:1` |

`N:n` advances `n` T-states without contention sampling. `C:n` first applies the delay for the current contention phase, then advances.

## Floating Bus and Snow

The CPU and ULA data buses are separated by resistors rather than a fully isolated tri-state buffer. An unattached port read can therefore sample the ULA-side bus:

- bitmap byte during a bitmap fetch;
- attribute byte during an attribute fetch;
- `0xFF` while idle or generating border/blanking.

The Z80 samples an I/O input at the end of the I/O machine cycle. Compute the bus value for that exact T-state after all contention delays.

RAMSOFT's measured convention places the first active-line values for a 48K model at:

| T-state | Value |
| ---: | --- |
| 14347 | `0x4000` bitmap |
| 14348 | `0x5800` attribute |
| 14349 | `0x4001` bitmap |
| 14350 | `0x5801` attribute |
| 14351-14354 | idle |

These figures use RAMSOFT's sampling convention and are intentionally distinct from the first-contended-cycle number. Reconcile origins before using either table.

When `I` is in `0x40-0x7F`, Z80 refresh addresses can interfere with ULA video access and cause the snow effect. Model this only with a clear fidelity target. It is not equivalent to random noise: measured descriptions retain ULA high address bits while low address behavior is influenced by `R`, producing wrong but structured video fetches.

On a 16K machine, reads above `0x7FFF` are physically unmapped. Do not assume a universal constant without checking the board/bus model and ULA activity.

## Port FE, Keyboard, Tape, and Sound

The ULA responds to I/O addresses with A0 low, not only literal `0x00FE`.

On output:

- bits 0-2 select border colour;
- bit 3 drives MIC/tape output;
- bit 4 participates in EAR/speaker output;
- higher bits are not border colour.

On input:

- bits 0-4 are active-low keyboard columns;
- A8-A15 select one or more active-low keyboard half-rows;
- bit 6 is EAR/tape input;
- idle and issue-dependent bits must follow the selected model.

When multiple rows are selected, combine their active-low results electrically. Verify CAPS SHIFT and SYMBOL SHIFT combinations and ghosting boundaries separately from the ROM's software rejection of invalid three-key combinations.

MIC and EAR output levels feed an analogue network whose behavior differs between board issues. Keep:

- cassette EAR input;
- MIC output;
- EAR output latch;
- mixed speaker level

as distinct concepts even when the host audio path simplifies their amplitudes.

Border and speaker changes are T-state-visible. Timestamp port writes at the actual I/O bus phase, not at instruction completion.

## Interrupts and Revision Boundaries

The ULA asserts maskable `/INT` once per frame. The standard ROM uses IM 1 and enters `0x0038`, increments `FRAMES`, and scans the keyboard. Hardware emulation must still work with interrupts disabled, IM 2 software, HALT, custom handlers, and an interrupt request that is asserted near instruction boundaries.

The ULA book distinguishes multiple silicon versions and implementation defects. Relevant audit boundaries include:

- early versus later display timing;
- I/O contention/decode fixes and board modifications;
- DRAM refresh behavior;
- variable pixel widths and snow;
- FLASH edge artifacts;
- analogue colour and chroma differences;
- issue-dependent EAR/MIC speaker levels.

Do not expose one synthetic "all ULA versions" device if software-visible timing is drawn from incompatible revisions. Either choose and document a concrete default or make the revision a configuration axis.

## Audit Invariants and Test Oracles

- `224 * 312 == 69888` PAL CPU T-states per frame.
- `224 * 264 == 59136` NTSC CPU T-states per frame under the book's geometry.
- The first and last active bitmap bytes use the documented nonlinear address mapping.
- One character emits exactly eight pixels from one latched bitmap byte.
- Attribute changes take effect according to the fetch/latch pipeline, not host draw order.
- Every contended M-cycle independently samples contention and shifts later accesses.
- Odd and even I/O ports follow the four contention-pattern classes.
- Floating bus returns the scheduled ULA byte only at the correct sampling edge and `0xFF` while idle.
- Keyboard rows are selected from the high address byte and combined active-low.
- INT phase remains stable across framebuffer, audio, and CPU scheduling.
- A ROM routine running from contended RAM observes the same waits as arbitrary user code.

Useful compatibility probes:

- RAMSOFT floating-bus self-test.
- Border stripes generated by cycle-counted `OUT (0xFE),A`.
- Contended versus uncontended instruction timing microtests.
- IM2 handlers with vector table or code in contended RAM.
- Vectron-style `I=0x40` snow probe when modeled.
- Arkanoid, Sidewize, Cobra, Duet, and DigiSynth as secondary software checks.
